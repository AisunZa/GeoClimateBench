# Methodology and scientific contract

## Scope

This proof-of-concept evaluates a July 2022 temperature-extremes workflow with a 1991–2020 reference period. It is built to reveal common scientific AI-agent mistakes: wrong temperature units, mislabeled time axes, incorrectly computed percentiles, false heatwave event lengths, omission of missing-data exclusions, and incorrect numerical error metrics.

The default fixture is *synthetic*. Parameter choices are operational definitions, not uniquely correct meteorological standards.

## Task 01 — temperature QC and daily maxima

**Input:** `t2m(time, latitude, longitude)` in kelvin. Times must be sorted, unique, exact UTC hours; coordinates are EPSG:4326 geographic latitude/longitude, strictly increasing.

1. A value is accepted if finite and in [180, 340] K; invalid values are NaN.
2. For each UTC calendar day and grid cell, count QC-accepted samples (`hours_valid`).
3. If count >=18, `tmax_c = max(valid hourly t2m) - 273.15`. Otherwise `tmax_c = NaN`.
4. No interpolation or gap filling. Day groups can be noncontiguous across years; the fixture samples summer windows only.
5. Output grid dimensions: `(time, latitude, longitude)`; `time` values are midnight UTC of sampled dates.

This is the **maximum of sampled hourly values**. A continuously observed real daily temperature maximum can be higher.

## Task 02 — summer exceedances and heatwave episodes

**Baseline:** 1991 through 2020 inclusive. Evaluation: July 2022 (complete 31 days required).

For each target day `d` and grid cell `(lat,lon)`, gather baseline daily maximum temperatures for **all baseline years** within ±7 calendar days of the target month/day (15-day window, inclusive). Use a 365-day month/day calendar so leap-year dates in July align correctly; February 29 is unsupported and raises an exception if encountered. For July, window coverage is June 24–August 7.

At each cell/day:

- Require ≥300 finite baseline temperatures (up to 450 possible samples for 30 years × 15 days).
- Require measurements from ≥20 distinct baseline years.
- Compute `threshold_c = nanpercentile(samples, 90, method="linear")`.
- Mark `exceedance_day` if target daily max is **strictly greater than** this threshold; equality is not an exceedance.
- Mark `heatwave_day` for every date belonging to a contiguous episode with ≥5 consecutive exceedance days. Missing temperature, missing threshold, and date gaps interrupt runs.
- Record `event_count`, `heatwave_days`, `max_event_length` per grid cell.

The monthly target period truncates episodes that continue across a month boundary. Events touching a boundary should not be treated as fully observed; expanding to shoulder dates is a planned improvement.

## Task 03 — station-to-grid matching and error statistics

**Inputs:** daily grids from task 01, station CSV with `station_id,date,latitude,longitude,txk_c`.

1. Reject duplicate station/date rows, out-of-range coordinates, and a station whose coordinates change through time.
2. Find the nearest model grid cell for each station by **great-circle haversine** distance (spherical Earth radius 6371.0088 km). Reject stations farther than 180 km from all available grid cells. Do *not* use unlabelled interpolation.
3. Drop station rows with absent/invalid TXK, `-999` missing sentinel, dates unavailable in grid, and grid cells with missing daily Tmax. Record every reason and row count. Keep any other unusually large but valid error; avoid cherry-picking observations.
4. Define signed error as `e_i = model_i - observed_i` (°C). Calculate
   - `bias = mean(e_i)`
   - `MAE = mean(abs(e_i))`
   - `RMSE = sqrt(mean(e_i**2))`
   - `max_abs_error = max(abs(e_i))`
   - `n_pairs = number of valid matched rows`
5. Export matched rows, per-station and global metrics, and explicit caveats.

**Interpretation risk:** DWD `TXK` is a recorded daily maximum and its measurement window may differ from 00:00–24:00 UTC; verify station-specific dates and observation conventions before interpreting systematic offsets. Terrain, land use, topography and reanalysis representativeness also differ.

## Synthetic fixture design

Generated by `geoclimatebench.fixtures.make_synthetic_dataset(seed=2026)`:

- 5 × 4 small geographic grid covering sample coordinates in and around Germany.
- Hourly readings for June 24–August 7 in 1991–2020, plus July 2022.
- Smooth synthetic diurnal/seasonal gradients, random perturbations (fixed seed), and artificial temperature events, including hot periods at 52.0°N, 13.5°E.
- Invalid `999 K`, missing values, and a cell/day with insufficient samples.
- Synthetic station observations derived from the generated grid with seeded noise, a `-999` station sentinel, one anomalous but valid observation and an out-of-domain station.

**No variable in this fixture is a real Earth observation.** Numerical RMSE reported against synthetic stations validates the benchmark *code*, not ERA5 skill.

## Grader

The public local verifier reconstructs canonical solutions from the fixture and compares submitted NetCDF variables, coordinates, derived metrics, station pairs and metadata at absolute tolerance `1e-4`. It also verifies that heatwave-day masks are subsets of exceedance masks and that day totals agree.

Unit tests are partly independent of the canonical implementation: fixed numerical results are calculated analytically for simplified two-year reference distributions, known hourly temperatures, signed errors, calendar gap cases, missing values and duplicate dates. An intentional mutation test verifies detection of a fabricated event count. Nonetheless a public oracle and verifier **are not security-separated**, so task scores cannot be claimed as externally evaluated model capabilities.
